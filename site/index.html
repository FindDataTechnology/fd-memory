Long-term memory for agents

Sessions end.
Memory doesn't.

YongYi turns everything an agent used to know — notes, handoffs, facts, experience — into structured knowledge recalled on every turn. Come back in a new session, or a quarter later, without re-explaining the background.

    01

    Four layers · L0 → L3

    One layer straining to hold everything is not the design. Four layers each do their own job: a write is recallable immediately, and after recall, supersede decides which version to trust.

    • L0 observations

      The raw event stream. Every tool call, every turn, every round trip lands with its original timestamp — not evaluated, not rewritten. This is the raw material distillation works from.

    • L1 notes + handoffs

      Notes you write and handoffs between members. A note enters two-dimensional recall immediately (query-relevant top-3 plus recent top-5). About a minute later write-triggered distillation picks it up; at roughly two minutes it is searchable as L2.

    • L2 facts + experiences

      Distilled structured knowledge. Retrieval scores every page in the store (vectors plus field weighting), so a page that shares no wording but is nearest in meaning stays reachable.

    • L3 profiles (roadmap)

      User preference profiles: cross-project preference extraction aggregated per owner, injected to answer "who is this user". Currently a roadmap item.

    02

    Three recall lanes

    Full-vector retrieval removes the keyword gate; field weighting keeps keywords meaningful; two-dimensional note recall guarantees anything just written can be found.

    Vector · whole-store scan

    semantic

    No longer limited to "candidates the keyword pass returned". Vectors score every page in the store — a page sharing no wording but nearest in meaning stays reachable, and its score is its rank.

    Keyword · field weighted

    title ×3 / keys ×2 / body ×1

    Still steady when embedding is slow: a title hit scores 3, a search key 2, body 1. A title hit is the real subject; a passing mention in the body earns nothing.

    Note · two dimensions

    query ≤3 + recent ≤5

    Recency is not the only door — relevance is. Query-matching notes come first, then recency fills up to five. Together, an old note is reachable without being recent.

    03

    Supersede

    Something changed? The latest conclusion is the one to trust. The old version stays queryable for audit, but the reading surface only ever shows the newest one.

    There is no "which version is right" dispute — the superseded version exists for audit and retrospect only; the reading surface always returns the newest conclusion.

    04

    Five-minute quickstart

    The CLI mints a first bootstrap token, you use it to mint one person-root token, and then you can ask the memory — no external user's token anywhere in the path.

    01

    Install dependencies and build (Node ≥ 22.5)

    npm ci && npm run build

    02

    Start it locally (built-in SQLite + FTS, zero external dependencies)

    ./dist/index.js serve --port 4000 &
curl http://127.0.0.1:4000/healthz  # → {"status":"ok"}

    03

    Mint a bootstrap token (CLI bootstrap)

    ./dist/index.js token mint \
  --kind platform --namespace '*' \
  --label bootstrap

    04

    Mint a person-root token with it, then ask the memory

    curl -X POST localhost:4000/admin/mint \
  -H "authorization: Bearer $BOOT" \
  -d '{"namespace":"u/demo"}'
# person token → /digest

    05

    Connect it to your AI client

    One command wires up MCP mounting, turn capture, a discipline block and an identity binding. The capture shape differs per client — read that column before you start, because it decides what you can expect.

    One command:

    yongyi connect <harness> --url http://127.0.0.1:49375 --as you@example.com
    ClientCapture shapeStatus
    Claude Codeshell hookverified end to end
    ZCodeshell hookconfigured, not proven
    WorkBuddyshell hookverified end to end
    Gemini CLIshell hookblocked by upstream quota
    Qwenshell hookcapture verified
    Hermesshell hookverified end to end
    Qodershell hookverified end to end
    OpenClawin-process bridgeverified end to end
    OpenCodein-process bridgeverified end to end
    Piin-process bridgeverified end to end
    Traepost-run harvestverified end to end (not live)
    Coze—not supported (no HTTP MCP transport)

    Three shapes, three behaviours. A shell hook forwards events live from the client's own hook configuration. An in-process bridge is a small module the client loads, calling the same hook command — it runs inside the client process, so it must never break your turn. A post-run harvest reads the file the client writes when a run ends; Trae has no hook surface at all, so its capture is not a live hook and there is no mid-turn recall.

    The acceptance criterion is a memory page, not an exit code. After a real turn, a page must appear under your owner's root:

    <FD_MEMORY_DATA>/owners/u-<you>/wiki/default/observations/*.md

    A hook exiting 0, a config file containing a hook entry, or a CLI printing "connected" are not evidence. The page is.

    Disconnecting never deletes memory. yongyi disconnect <harness> removes every managed artifact — the MCP entry, the hook wiring, the discipline block — while every memory page written under that root stays queryable. Other tools' hooks and your own content in the same files are left exactly as they were.

    Full per-client recipe, every pitfall, and the Windows-only traps: harness-integration.md. Pairing with Facet (skills and MCP tool surface) closes the other half of the loop.
